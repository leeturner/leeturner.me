A WireMock extension that adds a naughtyString Handlebars helper, so templated responses can return strings from the Big List of Naughty Strings (BLNS): SQL injection, RTL text, zero-width characters, emoji, Zalgo text and more. Every client test that hits the stub then exercises those cases for free.

{
  "request": { "method": "GET", "url": "/user" },
  "response": {
    "status": 200,
    "headers": { "Content-Type": "application/json" },
    "body": "{ \"name\": {{{toJson (naughtyString category='sql-injection')}}} }",
    "transformers": ["response-template"]
  }
}
  • Targets WireMock 4.0.0-beta.41 and runs on Java 17 or later.
  • The list is bundled in the JAR. Nothing is downloaded at runtime.

Warning

These are real payloads. The XSS, SQL and command-injection strings reach whatever consumes the mock, including logs, databases and browsers. That is the point, so only point clients at these stubs in environments where that is safe.

Install

There are two artifacts. Each only works in its own setting, so pick the one that matches how you run WireMock. The latest <version> is on the Maven Central badge above.

Artifact For
io.github.leeturner:wiremock-blns-extension Embedded WireMock (org.wiremock:wiremock, JUnit)
io.github.leeturner:wiremock-blns-extension-standalone The wiremock-standalone JAR and the Docker image

wiremock-standalone relocates Handlebars to wiremock.com.github.jknack.handlebars, so the standalone artifact is built against the relocated packages. The wrong one fails at runtime (the plain JAR in standalone WireMock throws AbstractMethodError).

Embedded (Java / JUnit)

Gradle:

testImplementation("io.github.leeturner:wiremock-blns-extension:<version>")

Maven:

<dependency>
  <groupId>io.github.leeturner</groupId>
  <artifactId>wiremock-blns-extension</artifactId>
  <version><!-- version --></version>
  <scope>test</scope>
</dependency>

The artifact has no dependencies of its own: it uses the WireMock already on your classpath. Register the extension:

@RegisterExtension
static WireMockExtension wm =
    WireMockExtension.newInstance()
        .options(wireMockConfig().dynamicPort().extensions(new BlnsExtension()))
        .build();

Or let WireMock find it with extensionScanningEnabled(true).

Standalone JAR

Download wiremock-blns-extension-standalone-<version>.jar from Maven Central and put it on the classpath next to wiremock-standalone:

java -cp wiremock-standalone-4.0.0-beta.41.jar:wiremock-blns-extension-standalone-<version>.jar \
  wiremock.Run --root-dir path/to/stubs

Standalone WireMock scans for extensions by default, so no --extensions flag is needed (unless you pass --disable-extensions-scanning).

Docker

Mount the standalone JAR into /var/wiremock/extensions/:

docker run -p 8080:8080 \
  -v "$PWD/wiremock-blns-extension-standalone-<version>.jar:/var/wiremock/extensions/blns.jar" \
  -v "$PWD/mappings:/home/wiremock/mappings" \
  wiremock/wiremock:4.0.0-beta.41

This is the same directory as in WireMock 3.x, and has been checked against wiremock/wiremock:4.0.0-beta.41.

Helper reference

Stubs need the response-template transformer (or global templating) as usual.

{{naughtyString}}                                  {{!-- random, from the whole list --}}
{{naughtyString category='Emoji'}}                 {{!-- random, from one category --}}
{{naughtyString category='sql-injection'}}         {{!-- category given as a slug --}}
{{naughtyString index=42}}                         {{!-- fixed entry from the whole list --}}
{{naughtyString category='Emoji' index=0}}         {{!-- fixed entry within a category --}}
{{naughtyString index=(randomInt lower=0 upper=10)}}
Parameter Meaning
category Limit the choice to one category. Matched case-insensitively, by heading (SQL Injection) or slug (sql-injection). See Categories.
index Return a fixed entry instead of a random one, counted from 0 within the whole list or within category. Use it to get the same string every time.

With neither, the helper picks at random from all 516 strings.

Bad input returns an error string, the same way WireMock’s built-in helpers do:

  • an unknown category gives [ERROR: Unknown BLNS category 'x'. Known: reserved-strings, …];
  • an index outside the range gives [ERROR: BLNS index 600 is out of range 0-515]. It does not wrap around, so a typo can’t quietly return the wrong string.

JSON bodies

WireMock doesn’t escape helper output, so a naughty string dropped straight into JSON will often break it (", \, control characters). Wrap the helper in WireMock’s toJson helper, which adds the quotes and escaping, and leave the value unquoted:

"body": "{ \"name\": {{{toJson (naughtyString)}}} }"

This is tested against every entry in the list: all 516 come back as valid JSON that parses to the original string.

Use body, not jsonBody. Inside a jsonBody string value ("name": "{{{toJson …}}}") the quotes double up and the result is invalid JSON.

Building

Building needs JDK 25 (see .sdkmanrc); the JARs target Java 17.

./gradlew build                          # tests plus the standalone smoke test
./gradlew test smokeTest -PtestJava=17   # run the tests on a Java 17 JVM
./gradlew shadowJar                      # build/libs/wiremock-blns-extension-<version>-standalone.jar

Publishing a GitHub Release publishes both artifacts to Maven Central, with the version taken from the tag (v1.2.3 → 1.2.3).
